### 丰富度基准是什么

拆开三分大赛那 11 条，"丰富"由三个维度构成，本轮四个模式都按这个补：

| 维度 | 三分大赛的做法 |
|---|---|
| **开场与介绍** | `contest_start` / `contest_host_intro` / `contest_opponent_intro` |
| **过程里程碑** | `contest_moneyrack`（花球架）/ `contest_finalrack`（最后一架）/ `contest_final10`（最后10秒） |
| **结果分档** | 不是一条"结束了"，而是 `advance` / `eliminated` / `champion` / `runnerup` 四档 |

**结果分档是关键**——同样是赢，冠军和亚军要说不一样的话，玩家才觉得系统"看见了"他的表现。

## 2. 命名与格式规范（必须遵守）

| 项 | 要求 |
|---|---|
| 目录 | `assets/aiba-audio/voices/` |
| 格式 | **`.mp3`**（96kbps 单声道即可）。老的 262 条 wav 保持不动，两种格式可共存 |
| 命名 | `<前缀>_<事件名>_<序号两位>_en.mp3`，例如 `p_battle_start_01_en.mp3` |
| 序号 | 从 `01` 连续。同一事件的多条是**随机池**，游戏每次随机挑一条 |
| 时长 | **不超过 2.5 秒**。玩家正在瞄准出手，长台词会盖住操作节奏 |

前缀：`p_` PA 公共播报（清晰、转播感）／`dj_` DJ 解说（兴奋、短促、有冲击力）／
`r_` 队友对手近距离（带喘息）／`ref_` 裁判哨（无语言）／`ui_` 界面音（无语言）。
音色沿用 `VOICE_SELECTION.md`。

## 11. 交付后怎么接进游戏（给写代码的 AI）

1. 文件放进 `assets/aiba-audio/voices/`，**必须和代码改动一起提交**，否则线上是一串 404。
2. 在 `src/audio.js` 的 `AUDIO_EVENTS` 里登记事件。
   **新批一律写全名带 `.mp3`**（老条目不带扩展名、默认按 `.wav` 解析，两者可共存）：
   ```js
   battle_start: ["p_battle_start_01_en.mp3", "p_battle_start_02_en.mp3", "p_battle_start_03_en.mp3"],
   ```
3. 在触发点用 `playAudioEvent("事件id")` 替换原来的 `paSay(...)`，**保留原调用作兜底**：
   ```js
   if(!playAudioEvent("battle_start"))paSay("百分大战开始!先到一百分获胜!",true);
   ```
4. **改完 `src/**` 一定要 bump `index.html` 里对应的 `?v=` 缓存 token。**
   上一批配音就栽在这里：文件改了、token 没动，浏览器一直用缓存副本，
   运行期 `AUDIO_EVENTS.lastshot_commentary_g7` 是 `undefined`——
   **23 条语音一条都没响，而且不报任何错**。
5. 跑 `node scripts/check.js`。它会检查每个已登记事件都有实际触发点
   （报错形如 `AUDIO_EVENTS entry has no direct trigger xxx`）。
6. 验证**不要靠耳朵**：用 `AUDIO_EVENTS[id]` 看登记、`fetch(url,{method:"HEAD"})` 看文件可取，
   全程静音即可（`scripts/silence-browser.js`）。


`world-places.js` 新增的 `facing(batch, ox, oz, rot)` 是本轮的布局单位：局部坐标里立面在 z=0、街在 +z、开间沿 x，`rot` 只取 0/±90/180，所以世界里仍是轴对齐盒子。同一段立面代码能贴到四条街上。
⚠ 合批的欧拉序是 XYZ（R=Rx·Ry·Rz），局部 X 轴倾斜没法和 `ry` 叠加 —— 所以 `facing` 不给盒子 yaw，而是换算尺寸并按朝向选 `rx`/`rz`。加新朝向时照这个来，别直接传 `ry`。

## 追加轮次（同日，用户点名的五件事）

### A. 湘南整体重构：铁道搬到篮筐正后方

用户原话："地铁在篮球框背后，这样可看到铁轨和火车，包括电线杆"。
海岸带从"球场左侧 x=−19 一线"整体转到 **−z 方向、沿 x 横铺**：

```
球场 → 人行道(抬高 .19) → 沿海公路 → 电线杆+架空线 → 铁道 → 低护栏 → 沙滩 → 海
        z=-14.4        z=-18        z=-21          z=-23.4  z=-26.4   → z=-40
```

- **电车沿 x 横穿画框**，从篮板后面驶过（车身仍沿 z 建模，整组 yaw 90°，`s.train.axis="x"`）。
- 校舍移到公路的**内陆一侧**（z>−13），段位刻意不等距，在 z 17.5~26.5 留出空档给 QA 的 wide 机位。
- −x 补校门 + 围墙 + 自行车棚三个节点；朝海人行道上有自动販売機和两条朝海的长椅（长椅交给人群系统，上面真的坐着人）。
- **两个踩坑**：① 架空线段用 `|x1-x0|` 当盒子长度 —— 盒子被 rz 转过之后要用**斜边**，否则每段短掉 1/cos，接头留缝，画面上是一排断线；② 0.05m 的线在 25m 外只有约 2px，没有 MSAA 会碎成虚线，加粗到 0.09。
- **护栏高度是硬约束**：眼高 2.3m、护栏在 28m 外，一道 0.86m 的横杆会把它后面 18m 沙滩整片挡在视线下方（`ray_y = 2.3 − d·(2.3−h)/28`）。压到 0.6m 之后沙滩和海才读得出来。

### B. 雨林瀑布换成真的水材质

用户原话："现在的瀑布很稀疏，看起来都不像水流（不用方框模拟水流，用真的水流液体材质）"。

旧版是 3 条静止竖带 + 5 股 ×3 段循环平移的长方体，**18 个 clone 材质 = 18 个 draw call**，86m 外柱与柱之间的缝比柱本身还显眼。
换成 **ShaderMaterial 水幕**：三层不同频率/下落速度的竖向拉伸噪声（水股与速度差）、中心厚两侧薄、顶端从岩唇翻出、底部炸成白沫；顶点着色器让水幕越往下越宽并带极慢横摆。两级各一张，`fog:false` 保住 §9 明度阶梯的白端。flowerCourt 投篮机位 draw call **148 → 120**。

⚠ 两个后续修正：① 上面那级也加了水花片，结果是一条 18m 宽的横白条横在水幕中段，像棉花桥把瀑布拦腰截断 —— 水花只留给真正砸进水潭的那一级；② 岩台那档的雾团等高排成一排同样会截断水幕，数量砍到 18%、高度拉开。

**⚠ 换水材质引出的连锁问题**：旧水柱每帧构建期消耗 R()，换掉之后整条随机序列平移，雨林植被重新长回菜单环绕轨道里 —— 菜单又被树冠糊住。所以加了 `menuOrbitGap(s,x,z)`：落在环绕带上的树改成"高干高冠"（树冠底抬到机位以上，只剩树干经过），藤蔓直接跳过。**这类判定必须显式写，不能指望随机摆得刚好让开。**

### D. 供球员真的把球拿在手里

用户原话："传球人，现在没传球的时候，双手都是下放，没有持球的，球悬在他们胸前"。

根因：`passerBall` 直接挂在 `passer.g` 的 (0,1.12,0.32)，而两条胳膊只有传球那 0.3 秒动一下、其余时间垂着。
修法不是把球往手边挪，而是把它挂到投球手的 **`ballGrip`**（handRoot 下的持球锚点，和玩家蓄力出手、赛前演示用的是同一个），手动到哪儿球就跟到哪儿；再给两条胳膊一个不对称的持球姿势（持球手在球下方托、另一只手从中线横过来扶）+ 呼吸与重心起伏。传球从"把抬起的手放下来"一拍改成两拍：先收球到胸口，再双臂前送打直；球的飞行起点也改成**手的世界坐标**。`oppPasser` 同样处理。

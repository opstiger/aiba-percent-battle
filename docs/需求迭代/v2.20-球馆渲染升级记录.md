# v2.20 球馆渲染升级记录

> 记录时间：2026-09-01
> 目标：保持 voxel 美术、角色比例、UI 布局、玩法视角不变，把画面从"游戏直出"提到"室内篮球馆宣传图"。
> **这不是换色。** 换的是渲染层级：灯光分工、地板结构、背景层级、后期合成。

---

## 一、为什么原来"平"

原画面的问题不在色号，在四盏灯**亮度同量级**：`ambient .32 + hemi .34 + sun .8 + spot 1.0`。
谁都不是主光 → 全场平均亮 → 观众和主角一样白 → 视线没有落点。

地板同理：室内地面是 **1m 见方的双色棋盘格**。棋盘格在任何机位下都读作瓷砖或地胶，
因为真实木地板的识别特征全不在颜色上，在几何（细长条 / 每块深浅不同 / 沿板长的木纹 / 错落的端接缝 / 板缝暗线）。

### 1. 灯光（core.js）

四层，各司其职：

| 灯 | 值 | 职责 |
|---|---|---|
| `spot` (key) | `0xfff2d8` 1.75，angle .68 penumbra .55，`(0.9,14.2,0.2)→(0,0.9,-4.2)` | 唯一主光，照亮投篮区和木地板 |
| `rim` | `0x9ec4ff` 0.55，`(-5,4.5,-15)` | 篮筐方向冷色背光，勾主角轮廓 |
| `camFill` | `0xffe0b8` 1.15，**distance 12**，挂在 camera 上 `(0,-0.15,1.0)` | 补主角朝镜头那一面 |
| `ambient`/`hemi` | .13 / .20 | 只保证暗部不死黑 |

**两个关键细节，改坏过一次：**

- **`rim` 的高度**。原本放 y=7.5，地板法线吃到 0.42 的余弦 —— 等于又加了一盏顶光，
  实测把近处地板抬高约 30 个灰阶。压到 y=4.5 后地板只吃 0.24，而朝向篮筐的人物竖面吃到 0.91。
- **`camFill` 必须是有距离上限的点光**。主角离镜头 3~4m 拿满，12m 外的看台衰减到 3% 以下。
  用平行光或抬环境光做补光，会把观众一起提亮 —— 那就白改了。
  位置略**低于**视点：光走得更水平，竖直的人物吃满（N·L≈0.92），水平的地板只吃掠射角（≈0.56）。

### 2. 地板（court.js + visual-director.js）

`paintHardwood()` 按五条特征画：13.2cm 板宽、每块板独立色调、板面横向受光渐变、
沿板长的木纹曲线、错落端接缝、板缝暗线 + 亮边。外加 7 团大尺度色斑打散均匀感。

材质：`color 0xc7bfb6 / specular 0x7a6448 / shininess 40`。
**shininess 22 时高光糊成一大片等于没有；40 才收成读得出的一道光带。**
实测高光对近处地板贡献 +20 个灰阶（关掉 specular 148 → 开 168.5）。
再往上抬（70/110）反而变暗 —— 高光收窄后跑出了取样区，说明当前值就在合适的位置。

### 3. 背景层级（arena.js + spectators.js）

- **横幅墙是 `MeshBasicMaterial`，不吃灯** —— 球馆再暗它也满亮，是原画面最抢眼的一块。
  只能靠 `color` 乘算压：`0x555d6e`。
- 看台人群：`recede(色, 降饱和, 压暗压冷)` = (.46, .30)。**纯降亮度不行** —— 会得到
  一堆深色但依然刺眼的色块，饱和度才是"抢眼"的主因。
- 近场观众降得轻（.30/.16）：他们是中景，压狠了球场边就空了。
- 雾：near 34→**15**、far 70→**52**，雾色 `0x121826`（**比背景亮一档**，远处观众淡进"空气"而不是"黑洞"）。

### 4. 空气感（arena.js）

- **光锥**：打球半场上方的灯下挂开口圆锥，加色、不写深度、`opacity .18`。
  一旦"看得清"就不是空气而是一只实心灰锥子 —— 早期用 .5 就是这个效果，必须压到几乎察觉不到。
- **地面灯池**：一张加色平面，每盏灯画两样东西 ——
  一摊软光（"被照亮"）+ 一道很窄很长的镜面倒影（"反光"）。
  只有其中一样，要么像哑光胶地，要么像镜子。
  **必须压在 y=0.008 / renderOrder=-2**，否则加色会把 v2.19.9 的角色接地影冲掉。

### 5. 实时阴影（core.js / characters.js）

v2.19.9 试过一次并放弃，结论是"开关两图平均像素差只有 1.21/255，看不见却要付一整个阴影 pass"。
**那条结论的前提是"场景刻意平光"** —— 没有主光就没有阴影可读。v2.20 有了压过其它所有灯的
key light，前提不成立了，所以这次开。

只开一盏灯的阴影（key spot），只有角色和球投、只有地板收。看台/顶棚/广告牌全部不参与。

**灯位为什么要偏出来**：正上方的主光把影子压在人脚底下、被身体自己挡住 ——
实测只覆盖画面 **0.37%**，等于没做。偏到右前方 `(6.2,11.8,4.2)` 之后影子朝左前方拉开，
覆盖 **1.28%**，最深处压暗 74/255。**"落地感"来自影子的方向，不是影子的存在。**

两层影子现在是分工不是重复：
- 真实阴影 —— 有方向、随姿势变形，只在主光锥内有
- 原来的软影贴图 —— 降到三成强度当接触遮蔽（AO），并覆盖锥外的角色（传球人/替补）

`castShadow` 在 three 里**不沿层级继承**，必须逐网格设；装备/发型/胡子都是创建之后才挂上去的，
所以 `characters.js` 每 15 帧重扫一次（4 个角色 × 约 40 节点，一秒 4 次，可忽略）。

手机把阴影贴图砍到 512（≈10cm/纹素）：方块边本来就是硬直角，糊一点看不出来，填充率省四分之三。
`?shadows=0` 可以关掉。

> ⚠️ `spot.shadow.camera.far` 写了也没用 —— `SpotLightShadow.updateMatrices` 里是
> `light.distance || camera.far`，实际远平面等于 `spot.distance`。只有 `near` 需要自己给。

### 5.5 顺带修掉的一个静默失效（perf.js）

排查"阴影为什么不动"时发现：**三个差异极大的灯位，A/B 读数一模一样**。
根因是 `perf.js` 的静态矩阵冻结会把 `indoorRoot` 下的所有对象设成 `matrixAutoUpdate=false`，
而 `spot` / `spot.target` / `rim` 正好挂在 `indoorRoot` 上。
`matrixAutoUpdate=false` 时 `updateMatrixWorld` **不会再用 position 重算 matrix** ——
于是 `applyScenePreset` 里所有改灯位的代码全是空操作，改完画面一点变化都没有，也不报任何错。

这不是本轮引入的，是一直存在的坑（任何人改灯位都会撞上）。已让冻结跳过灯和它们的 target：
灯只有个位数，冻结省不下任何东西。

### 6. 后期合成（grade.js，新文件）

包 `renderer.render`，只接管主场景（装备预览等自带 scene/camera 的离屏渲染原样放行）。
三趟：场景→离屏 → 1/4 分辨率两遍高斯 → 合成到画布。

**一张模糊图两用**：减去阈值是泛光，按深度混合是景深。省掉一整条模糊链。

四个必须知道的实现约束：

1. **离屏 RT 的 `texture.encoding` 必须设成 `sRGBEncoding`**。
   实测这样出来的像素和直接画到画布**完全一致**（96.7/101.2/114.8 对 96.7/101.2/114.8），
   所以关掉效果时是像素级无损的。用默认的线性 RT，8bit 量化会在暗部压出色带 —— 这个场景很暗，不能这么做。
2. 合成材质是裸 `ShaderMaterial`，**不 include `<encodings_fragment>`**，three 才不会再编码一次。
   调色因此发生在显示空间（sRGB）里 —— 这也是绝大多数游戏调色的做法。
3. **对比必须带 toe**。围绕 0.5 线性拉对比会把整个暗部推进纯黑：
   实测画面上部近黑面积 **0% → 47%**，而灯光本身一点问题都没有 ——
   v2.19.9 好不容易补出来的顶棚桁架就是这么二次消失的。
   整体抬黑位（lift）解决不了，那会连地板一起洗白（实测 lift 抬到 +0.03 才降到 34%，代价是地板 +8 灰阶）。
   正解是按原始亮度调制对比强度：`shadowKeep .32 / toeEnd .26`，暗部只施加 32% 的对比。
4. **景深必须按真实深度**，不能按半径。按半径糊会把画面边角的主角一起糊掉。

**户外是另一套配方**（`LOOKS.outdoor`）。天空是一整片没有纹理的渐变，
室内那档暗角会在天上画出一道看得见的椭圆边 —— 那不是电影感，是穿帮。所以户外整体减半。
`applyScenePreset` 被包了一层，切场景自动换配方。

## 三、实测数据（同一机位、同一取景、投影锚定采样区）

练习模式 · 弧顶 · 球员跟随机位 · 1280×720

| 指标 | v2.19.9 | v2.20 | 变化 |
|---|---|---|---|
| 主角躯干亮度 | 177.1 | 165.8 | −6% |
| 看台观众 | 114.5 | **70.1** | **−39%** |
| 横幅墙 | 110.6 | **53.2** | **−52%** |
| **主角 / 观众** | 1.55 | **2.37** | **+53%** |
| 主角 / 地板均值 | 1.38 | **1.59** | +15% |
| 地板明暗差（灯池↔边线） | 26.0（1.23×） | **38.6（1.45×）** | 层次翻倍 |
| 地板·灯池 / 弧顶 / 左翼 / 边线外 | 135 / 122 / 140 / 114 | 124 / 109 / 85 / 98 | 原来几乎平，现在有落差 |

**结论**：主角只暗了 6%，背景暗了 39~52% —— 突出主体靠的是压背景，不是提主角。

**阴影**：覆盖画面 1.28%（正上方灯位时只有 0.37%），最深压暗 74/255。

性能（桌面 721×1148，各 5~6 组中位数）：
- 后期合成层 **+0.096ms/帧**（0.367 → 0.463ms）
- 实时阴影 **+0.214ms/帧**（0.634 → 0.848ms）

手机 GPU 填充率慢约一个数量级，所以两项都有降级路径：后期在 `deviceMemory≤2` 或 `?quality=low`
时不开、粗指针设备模糊链降到 1/8 分辨率；阴影贴图在粗指针设备降到 512。

## 五、试过但不采用

| 方案 | 结果 | 结论 |
|---|---|---|
| 靠抬 `lift` 救回顶棚暗部 | +0.03 才把近黑从 47% 降到 34%，地板同时 +8 灰阶 | 全局抬黑位会洗掉整张图，要用 toe |
| `shininess` 抬到 70 / 110 求"更亮的高光" | 近处地板反而 168 → 155 / 150 | 高光收窄后跑出取景区；40 就在正确位置 |
| 靠调灯位让看台变暗 | 灯位/强度怎么调，看台亮度都跟着地板一起动 | 这个距离尺度上物理衰减分不开，必须用材质降饱和 |
| 光锥 `opacity .5` | 读成实心灰锥 | 假体积光只能存在于"几乎察觉不到"的强度 |
| 主光放正上方 + 开阴影 | 影子被身体自己挡住，只覆盖 0.37% | 阴影要有方向才读得出来，灯必须偏出来 |
| 材质 Lambert → Standard（HY4 建议） | 未采用 | Standard 是 PBR，没有 envMap 时金属/粗糙度读不出来，
反而比现在的 Lambert+Phong 组合更平；v2.19.9 已验证粗暴换材质会洗白看台。地板已经是 Phong 带高光，
真正需要质感的那一块已经覆盖了。要做就得连环境贴图一起做，属于另一个量级的改动 |
| 顶灯改成真 PointLight（HY4 建议） | 未采用 | 6~14 盏点光，而看台/角色是 Lambert（逐顶点着色），
大方块上会出现明显的顶点插值断层；自发光灯箱 + 地面灯池 + 光锥已经给出同样的"灯在发光"读感，代价接近零 |

**注意**：ACES 色调映射、真实阴影贴图在 v2.19.9 已验证不可用，
理由见 `v2.19.9-质感与公平性迭代记录.md`。本轮的 toe 曲线是自定义的，不是 ACES。

## 七、v2.20.1 角色自阴影（characters.js）

v2.20 把真实阴影打开了，但角色**只投影、不接影** —— `markShadowCasters()`
只设了 `castShadow`，全项目 `receiveShadow` 只有两处（地面 `court.js:138`、
第一人称镜像臂关闭）。于是手臂压在躯干上、头压在脖子上、头发压在额头上的
暗部一个都没有，角色还是读作"贴纸"。

`castShadow` 和 `receiveShadow` 在 three 里都**不沿层级继承**，必须逐个网格设。
补上之后角色既投影也接影，多人场景里彼此的影子也会落在对方身上。

**拿到的数据**（`scripts/selfshadow-ab.test.mjs`，同一帧状态下开关、读 WebGL 像素做差）：

| | 桌面 1024 贴图 | 手机 512 贴图 |
|---|---|---|
| 角色区受影响像素 | 10.8~12.1% | 20.2% |
| 新增孤立暗点（acne） | **0~1** | **0~1** |
| 单帧增量 | +0.11ms（+5.5%） | 噪声内（约 0） |

变暗像素远多于变亮像素（90553 : 0），符合阴影只会压暗的物理，没有异常翻亮。

### 这个测试台为什么这么写

- **不截图对比**：运镜和演出随机走 `Math.random()`，截两次连人物站位都不一样，
  差异里混着噪声。改成同一帧状态下把 `receiveShadow` 开关一次、`readPixels` 读两次，
  两次之间除了这个开关没有任何变量。
- **`preserveDrawingBuffer` 用 `addInitScript` 注入**，不碰生产代码。
- **`?fx=0` 关后期**，排除 grade.js 的色调/暗角干扰，只看阴影本身。
- **性能走 ABAB 三轮取最小值**：单轮 AB 测出过 −0.27ms（开销不可能是负的），
  那是 GPU 调度噪声；最小值对应"这次没被打断"。

**踩过的坑**：`AA_COARSE_POINTER` 的判据里有 `Math.min(innerWidth,innerHeight)<700`，
所以竖屏 420×860 **也算粗指针**、贴图是 512。早先拿它当"桌面"跑，报出来的 mapSize
是 512，等于没测到桌面路径。桌面档必须用短边 ≥700 的视口（现用 1280×800）。

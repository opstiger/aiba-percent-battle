## 关键技术决策

1. 第三人称球员骨骼与 `shot-motion.js` 姿势是唯一动作真源。第一人称只能镜像，不得再维护第二套蓄力/出手曲线。
2. 投篮物理只使用真实球员持球锚点 `pBall`，不得使用相机专用 `handBall`。
3. 新逻辑只能写入 `src/`，禁止向 `index.html` 新增内联游戏逻辑。
4. 每次业务代码修改都要先做可回滚备份并升级版本。小修复升补丁号，例如 `2.18.1`；新功能或大修复升次版本号。
5. `index.html` 必须与当前版本快照逐字节一致，然后运行 `node scripts/check.js`。
6. 浏览器自动化只用于冒烟检查。投篮手感、体感控制、镜头、录屏和 iPhone 性能必须人工或真机验收。

## 未解决与验收缺口

- `v2.18` 仍缺一次人工第一人称长按验收：下蹲、举球、出手、压腕跟随、辅助手回收、出球位置、落地、晚释放和回到待机都应与第三人称一致，不能闪动或跳姿势。自动化长按没有形成可靠证据。
- 当前本地成果尚未被 commit/tag 保护，这是最高仓库风险。
- 计划中的 `v2.19` 摄像头预览折叠尚未实现。目标为三态：展开预览；折叠为贴边小条但继续体感识别；显式关闭才停止摄像头。iOS 上不得对处理中的 video 使用 `display:none`，折叠时只停预览 canvas 绘制；精彩录屏也应隐藏已折叠的摄像头画中画。
- 第一人称改动后，iPhone 竖屏取景、快速手势识别、性能及终局录屏仍需真机回归。
- `docs/ARCHITECTURE.md` 和 `docs/需求迭代/当前需求待办.md` 仍有少量重构期旧表述。可参考其中的所有权清单，但继续工作前要以当前文件为准核实状态。

## 不要重复的方案

- 不要从 `篮球游戏-refactor-v2/` 继续开发，也不要把该旧实验整体合并回来。
- 不要恢复无骨骼 GLB 球员实验；在具备可靠骨骼模型管线前，3D 模型替换已明确暂停。
- 不要再写独立第一人称姿势曲线，也不要从 `handBall` 或相机状态计算出手点；这两种做法都会造成第一/第三人称不一致。
- 体感识别运行时，不要用 `display:none` 隐藏摄像头 video；iOS 可能暂停或扰乱帧输入。
- 不要把浏览器自动长按当成动作验收。非音频测试必须静音，并在测试结束后关闭临时页面和进程。

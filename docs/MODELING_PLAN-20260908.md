### 这一段里被自己抓掉的四个假结果

写下来是因为它们都"看起来像产品 bug"，实际都是测法错：

1. **四种球鞋全红，装备"被甩离脚踝 0.9m"** —— 我按数组下标配对脚踝，而 detail 下每只脚
   push 两组（脚+趾）、classic 只 push 一组，顺序根本不同，于是拿左脚装备去比右脚踝。
   改成沿父链找真正的宿主踝，数值立刻回到 0.19m。
2. **"离踝距离比 classic 大 24mm"** —— 这个差是脚趾关节带来的**正常行程**，不是故障。
   刚性挂载的判据应该是"局部坐标不变"，不是"世界距离不变"。
3. **"脱光后网格数反而少 10 个"** —— 基线是在上一子测试还穿着鞋时量的，起点就错了。
4. **前臂半径量出 0.0mm，断言永远绿** —— 前臂是圆角软体素，最外那圈顶点是圆角极点，
   半径本来就是 0；改百分比带又因为几何只有 2 段而带内一个顶点都没有。
   最后改成先列"半径-高度"剖面再插值，才拿到真实的 −7.7mm。

变异测试验过断言不是空的：把前掌件改挂 `foot` → ②红；把 toeKit 挂到角色根 → ①红。

## v2.24 · 球架摆位与取球动作（接手续做）

### 上一版错在哪

球架摆在球员**身后 0.85m** —— 那个位置人根本够不着,所以只能让球自己飞到手里。
用户一眼看出来:"球员都不是伸手去拿,你是直接飞过去的,不真实。"

真实三分大赛的架子是**立在投篮点旁边**的,球员侧身双手把球端起来。

### 改了什么

| 项 | 实现 | 实测 |
| --- | --- | --- |
| 摆位 | 移到惯用手一侧:`spot + perp*side*0.95 - dir*0.10` | 横向 0.95m / 后撤 0.10m |
| 坡度朝向 | 右侧架整体转 180°,局部 +X(最低格)永远指回球员 | 最低球离**球员** 0.36m,最高 1.54m |
| 惯用手 | 新增 `hand:"left"`,`rackSideFor()` 决定 side | 哈登 side=−1,架子镜像到 −0.95 |
| 取球三拍 | 球先停在架上(0~46%),手过去抓,再一起收回 | 球在 0.86m 处静止 0.29s 后才移动 |
| 转身 | `G.pickupTurn` 加在朝向上,不是姿势里 | 峰值 **28.5°**,收球后归零 |
| 第一人称 | `rig.look` 按取球进度插向球架 | 原来死盯 HOOP,转身在 FP 里完全看不见 |

新增球星:**詹姆斯·哈登**(`h13`,13 号,`hand:"left"`)。放进 `CLASSIC_LEGENDS` 而不是
`coverStars` —— 后者需要封面视频/图,`cover-h13` 不存在,而且 check.js 锁死 5 个封面星。

### v2.25 补记：左手镜像做完了，上一段的"只做一半"已作废

### ⚠️ （已作废）左手投篮只做了一半

`hand:"left"` 目前**只决定球架在哪一侧、取球往哪边转身**。
**投篮动作本身仍然是共用的右手那一套。**

原因:投篮手写死成 `arms[0]` / `handRoots[0]` / `ballGrips[0]`,散布在 motion.js 和
shot-motion.js 的约 30 处。真要做左手有两条路,各有代价:

1. **交换绑定数组**(让 `arms[0]` 物理上是左臂)。改一处,30 个调用点不用动。
   但姿势里那些**四元数是按右臂写死的** —— 直接套到左臂上会绕错轴,
   需要再加一层镜像(x,y,z,w)→(x,−y,−z,w)。而出手关键帧被 check.js 锁到毫米级,
   这是全项目最敏感的一段代码。
2. **`g.scale.x = -1`** 整体镜像。姿势代码一个字不用改,但脸/号码贴图会镜像、
   三角形绕序翻转导致背面剔除和光照出问题。

两条都不是"顺手做掉"的量级,建议单独一轮做,并且先补一个"左右手关键帧互为镜像"的断言。

## v2.25 · 球架侧的正确规则 + 左手镜像

### 1. 我把坐标注释写反了（行为是对的）

上一版我写"perp 是球员的右手边、右手球员架子在右"。**`perp=(dir.z,0,-dir.x)` 其实是球员的左手边。**
结论歪打正着(架子确实落在辅助手一侧),但注释会把下一个人带沟里,已修正。

用户给的规则是对的:**架子放在辅助手一侧**。理由是蓄力时躯干朝辅助手一侧打开 ——
实测满蓄力下投篮臂前移 +0.097m、辅助臂后撤 -0.097m,架子放在已经打开的那一侧伸手才顺。

**别再靠推符号验证**,直接问"架子和哪只手同侧":
`toRack·toGuide = +0.99` / `toRack·toShoot = -0.99` → 在辅助手一侧。右手左手两边都成立。

### 2. 左手镜像:`g.scale.x = -1`，比我上一版说的简单得多

上一版我把这条路的风险说大了,说"三角形绕序翻转导致背面剔除和光照出问题"。
**错了**:three r128 的 `renderBufferDirect` 会检查 `matrixWorld.determinant()<0` 并翻转正面绕序
(`vendor/three.min.r128.js` 里能直接搜到 `determinant()<0`),背面剔除和法线都是对的。

所以整体镜像就够了,**姿势代码一个字没改** —— 接球、蓄力侧身、出手、跟随、踢腿全部自动反过来。

只有三个地方要补:

| 补什么 | 为什么 |
| --- | --- |
| 侧身/风格 turn 取反 | 它们是**世界偏航角**,在父坐标系里,不吃角色身上的局部 X 镜像 |
| 第一人称 rig 也 `scale.x=-1` | FP 手臂是克隆到 scene 下的,**不继承**球员的镜像缩放 |
| 号码贴图预翻转 | 几何翻一次 + 贴图翻一次 = 正的。缓存 key 必须带 mirror 标志 |

`pickupTurn` **不要**取反:它的方向已经由 `rackSideFor` 决定过一次,再反一次会背对球架。

### 3. 实测

```
投篮臂左右   右手 -0.2907 → 左手 +0.2907
辅助臂左右   右手 +0.3204 → 左手 -0.3204
前后/高低    fwd -0.0412 不变, up 1.373 不变
架子侧       两种手都是"对辅助臂 +0.99 / 对投篮臂 -0.99"
```

`scripts/shot-style.test.mjs` 加了 ③ 段守这条。判据是**互为镜像**,不是"数值不一样" ——
后者太弱。还额外断言"左右量本身 >0.15m",防止两边都是 0 时假绿。
变异测试:去掉 `scale.x` 取反 → 三条断言全红。

# 球场空间紧凑化与真实环境计划

日期：2026-09-10。供后续 AI 实施；本轮只分析、写计划，未修改游戏行为。

## 1. 目标与证据

用户当前优先级：解决球场与环境脱节、周围空旷、建筑植物零散的问题。保留 Minecraft 风格，每个地方有独立的城市或自然空间结构。先升级现有八张户外场地，暂缓增加新地图。

分析基于当前 v2.22.0 工作区、PROJECT_STATE 与 `artifacts/world-wonders-p1-20260910/` 八张 `*-play.png`，不是新的真机测试。接手时重新确认分支、版本和脏文件；当前工作区包含尚未提交的前轮成果。

代码事实：COURT 宽 15.24m，场地表面纹理覆盖宽 32m，左右各有约 8.38m 的场外铺装带。这个数值不是允许摆物体的安全区，也不代表每张图全部空着；它解释了统一大底板为什么容易产生广场感。左右底角投篮点已经在 x=±7.2，必须另算人物、球架、取球及镜头的活动范围。

画面判断：

- 雨巷：房屋之间露出没有终点的亮色缝隙；从门口到球场是一整片缺少用途的地面，屋顶高度和节奏接近。
- 西班牙：阳台等细节已有，但房屋仍像独立展品，楼间空隙直接通向天空，缺少连续街区与门前生活。
- 夕阳：海景开阔合理，但步道缺少人行节点，度假街区多数不在主要投篮画面内。
- 地中海：主要机位只读到右侧一小段白墙、花球和一条海带，村落的坡地层次没有充分进入画面。
- 湘南：铁道、电线与围网很明确，学校和放学生活的识别较弱；不宜继续只往远处加东西。
- 晴天：高楼已填满主要背景，问题转为近处街道生活、建筑首层与场地衔接，继续堆高楼收益有限。
- 雨林：已经最有包围感，下一步应梳理植被层次、根部接地和视觉主次，继续大量堆叶子可能更乱。
- 雪原：开阔是主题所需，但岸线、树林和雪面过于平直，近处缺少一个可信的使用场所。

## 2. 全场通用设计原则

### 2.1 先决定空间，再放物件

先画每场俯视图，标出建筑实心区域、开放景观方向、入口、步行线路和停留节点。将大地面分成有意义的区域：比赛地面 → 安全缓冲 → 场边设施 → 街巷/植被 → 建筑/地形。不能保持大空地不变，再随机撒花盆、自行车和人。

城市场做连片街区：一段连续立面有转角、有侧巷、有后面的第二排体量。房子可以共享墙、连在一起，也可以退进形成门廊；避免每栋房子都是四面完全暴露的相同盒子。

自然场做连片生境：草丛和树集中生长在土坡、岸线、树根、石缝附近，形成大小不等的团块，中间留下有去向的路径。避免左右等距排列一圈树。

### 2.2 先压缩没有用途的距离

以下是白模试摆范围，不是安全标准，也不能整圈硬套：城市场可先尝试让低矮场边设施落在边线外约 2–3m、面向球场的主要立面落在边线外约 4–7m；实际位置必须避开动作与镜头范围。建筑可以近低远高，形成错层。

球场尺寸、篮筐与取球坐标不动。优先重画场外铺装，接入墙脚、树池、步道和植被土壤；视觉上消除统一宽边。物理路径安全不依赖装饰纹理。

### 2.3 给主要画面一个侧边近景、一段中景、一个远景

近景可以是画面角落的一截雨棚、树冠或低墙；中景是门廊、街边座位、校门、台地；远景是楼群、山坡、海湾。各层彼此遮挡一部分，让人看出空间厚度。近景不横穿篮板、球员脸、持球手与投篮路径。

海边和雪原采用“一侧紧凑、一侧放开”，保留海和天空。城市与雨林可以更有包围感。不能给八场套同一套密度或天空占比。

### 2.4 每张场地先做三个有用途的小区域

建议首轮每场只精做三个节点，例如入口、休息点、生活角。每个节点是相互关联的组合：长椅旁有包和水瓶、树荫下有人坐；商店有门、雨棚和走得通的入口；校门连着自行车棚与人行道。其余空间保持简洁。

观众跟随地点重新布局：两三个人聊球、一个人在屋檐下等雨停、一个从巷子走过、楼上有人探头。人物的朝向、停留和反应由角色决定，不沿边线均匀排队。即使总人数不增加，也应能看出社会关系。

### 2.5 用地面和接触阴影把东西粘回世界

统一处理门槛到路面的连接、墙基、路缘、排水、树根和高差。磨损有成因：门口踩亮、树下落叶、路缘积沙、檐下较干、排水口附近更湿。大块材质变化先于细碎噪点。保留方块化大形，减少同尺寸小方块铺满一切。

## 3. 八场具体方向

### A. 雨天京都：嵌在町屋之间的社区球场（优先试点）

- 两侧用连续町屋和围墙收紧；靠近球场的是较低屋檐，第二排错落屋顶补厚度。留一条偏侧的窄巷通往后街，巷尾必须有转折、门或建筑，不能一眼穿到世界尽头。
- 球场入口接窄人行道，石板铺装延伸到商店门口；场边排水沟接入巷子，浅积水集中在低点，檐下有较干的区域。
- 三个节点：带暖光的街角小店、屋檐下的避雨长椅、靠墙自行车与伞架。人物集中在避雨处，少量撑伞路人沿巷子通行。
- 闪光点：下雨后球场外的生活仍在继续；偶尔有人从干燥屋檐下走到雨中，雨棚滴水与地面湿痕位置一致。
- 验收：主要机位能同时读到町屋首层、连续地面与一条有终点的巷子；不能只是把现有房屋等比例放大。

### B. 西班牙：从老街建筑中留出来的一块球场

- 把独立房屋重组为不规则 U 形街区，局部共墙；以两三个高低不同的组团替代一排尺寸相近的独栋。
- 两个出入口分别做台阶巷、转角拱道，出口后还有一段墙和屋顶。首层前移，较高楼层向后错开，避免高位镜头被屋顶整片遮住。
- 三个节点：老树下的石凳、转角小咖啡店、通往住家的短阶。花盆成组靠墙，晾衣跨越侧巷，窗户开合和阳台物品按住户变化，不每窗复制一盆花。
- 闪光点：观众来自不同高度——石凳上的邻居、店门前站着的人、阳台上偶尔看一眼的居民。
- 验收：遮掉细节只看建筑轮廓，也应像连续老街；门前铺装不会形成宽阔、无用途的空广场。

### C. 西海岸夕阳：海边步道上的开放街球角

- 面海方向保留落日与海平线；城市一侧用低层餐饮、冲浪店、酒店露台组成连续街边。建筑沿步道拐进左右画面，不把酒店全部放在镜头之外。
- 球场到步道接旧混凝土伸缩缝、磨损台阶、少量积沙；沙滩边缘做浅坡和弧形侵入，减少几条笔直色带。
- 三个节点：棕榈树下座椅、冲浪店前的板架与自行车、带遮阳棚的餐饮露台。保留宽敞通行开口，不加整圈铁网。
- 闪光点：夕阳变暗时，店内、露台串灯、酒店窗口分批亮起；同一条步道逐渐从沙滩休闲转成傍晚聚会。
- 验收：正常投篮画面的一侧能看见步道生活和街区，中央仍看到海；从侧面看不再是球场—大片沙地—远酒店三个断开的区域。

### D. 地中海：白色村落台地尽头的小球场

- 右侧白墙形成沿坡阶梯状聚落，近处低院墙、中部露台、后方第二第三层房屋互相搭接；部分组团延伸到篮筐侧后方，进入主要画面。
- 用石阶把球场侧门接到咖啡露台，再向下连接岸边路径；墙脚三角梅沿墙和门架生长，避免一排独立粉色球。
- 三个节点：蓝门小院、葡萄架/藤架下的露台、向海下行的石阶。用一处弯曲海湾或伸出的崖角构成中景，海上帆船保持远且少。
- 闪光点：站在球场就能看出村落高低关系，像走下几级台阶就进入邻居的院子。
- 验收：海的可见宽度不退步。先改建筑与台地几何，不能用更强雾或更亮天空掩盖海面被平台挡住的问题。

### E. 湘南：放学后的沿海校园边缘

- 学校一侧补完整校园边界：低围墙、校门、连廊、自行车棚及远处校舍；把能识别校园的入口节点布置到常用机位可见的侧后方。
- 道路—铁道—海堤现有横向关系已较紧，保留真实通行间距；在道路远处加入弯折和少量沿线住宅，避免所有线无限平行直伸。
- 三个节点：校门口结伴离开的学生、自行车棚、堤边的休息点。书包和校服有位置关系，少量当地居民与学生混合。
- 闪光点：一段电车从建筑/绿篱后出现，再沿海驶出；出场位置需经真实投篮镜头验证，不只在俯瞰图中可见。
- 验收：关掉地图名字仍能判断是校园海岸；加景不得挤入轨道、道路、球架和底角站位。

### F. 晴天都会：街区包围的城市球场

- 保留已有高楼尺度，重点补首层：连续店面、转角门厅、公交站与连通的人行道。高楼采用近处低层裙房、后方塔楼的深度关系。
- 场地围网开口要接真正的人行入口；道路在路口产生横向联系，远楼之间的缝隙用第二排体量补景，避免平面楼墙。
- 三个节点：便利店门前、公交候车区、球场入口的自行车与街球者。豪车、巴士、校车使用合理车道和间隔，不为热闹而频繁刷过篮筐背景。
- 闪光点：背景能读到等车、路过、买饮料与看球四种同时存在的用途。
- 验收：新增模型主要改善人眼高度的街道层，而不是继续重复上层窗格。

### G. 鲜花峡谷雨林：密林中被使用的小空地

- 保留当前树冠、峡谷和瀑布大结构，检查低层叶丛是否扎根；用苔石、板根、蕨类、落叶土壤连接大树与球场边。
- 植被组成大小不等的密团，留一条窄林间入口；树冠高度和间隙随地形变化，避免每一层都均匀铺满。
- 三个节点：林间入口、岩石旁的休息点、通向远瀑布方向的可读路径。路径不必可探索，但必须有连续去向。
- 闪光点：瀑布雾气附近更湿、更密，靠球场活动区域有踩踏与清理痕迹；环境有生长原因。
- 验收：保留原有得分生花机制；新增植物不把篮筐和人物埋住，密度不以新增叶片数量评判。

### H. 极光雪原：冰湖边有人维护的冬日球场

- 保留湖面和极光的大留白。将平直林线重组为两侧伸入、中间打开的林带，近处有成簇高低松树，远处有第二层山坡。
- 雪岸做凸凹不等的低坡，湖边弯曲，避免巨大矩形冰面。扫雪堆集中在清扫边缘，入口留出被踩实的小路。
- 三个节点：暖灯小木屋、放雪铲与木柴的维护角、靠近入口的短休息凳。人数少，衣着和动作保持冬季主题。
- 闪光点：从木屋到球场有脚印，边上有扫雪痕迹——一眼知道是谁在使用和维护这个地方。
- 验收：空间更有地形与生活依据，但仍然安静开阔，不能改成四面密房子或密森林的封闭球场。

## 4. 交付顺序

1. **空间白模**：先做雨巷和西班牙。只改组团、距离、高差、入口和大块铺装，用简单材质验证构图；先交相同机位的前后对比。白模仍空，就继续改布局，不进入小物件阶段。
2. **开放场地**：西海岸、地中海、湘南。采用近侧生活空间和远侧开放景观，逐张设计边界。每场必须有自己的俯视草图，不能复制同一组坐标换材质。
3. **针对性补齐**：晴天补首层生活；雪原补地形与维护节点；雨林补根部和植被层次。三者需要的工作量和密度不同。
4. **居民与动态**：在空间确定后重排观众、步行路线和少量事件。先用静态角色摆出可信关系，再加动作。
5. **接地与性能**：补阴影、磨损、接缝和远近简化，运行全场回归，记录剩余问题。

每阶段记录：已完成场景、修改文件、布局参数、对应截图、未解决问题、下一步。不得用“模型已添加”替代画面验收。资源不足时优先交付完整的两张试点，后续沿用方法与工具，保留每张不同的布局。

## 5. 实施技术要点

- 首要代码入口：`world-places.js` 六场 builder 与 surface；`world-wonders.js` 雪原/西班牙；`spectators.js` 观众布局与角色。光照只在空间调整完成后按需改 `environments.js` / `visual-director.js`。
- 建议引入轻量布局描述：建筑/地形组团、边界折线、入口、步行路径、停留点、禁止摆放区域；由当前 batch 与场景生命周期消费。先证明两场能复用，再抽公共代码，不建设庞大通用地图编辑器。
- 建筑用局部坐标组团，先确定面向街道的立面，再放门窗阳台。高低层可以独立退台，不要简单把所有楼搬近。
- 禁止摆放区域应包含人物与球架实际外形、取球动作、点位间移动路径、球的轨迹，以及镜头运动范围。包括五架、两个 DEEPS、中场点与相关玩法，不能只按 COURT 矩形加统一边距。
- 现有两新场 30 条相机到 HOOP 的射线只覆盖篮筐中心可见性；不能证明球员、手、投篮抛物线和转场不遮挡。先布置绕开镜头路径；必要时局部低墙或退台。相机专属隐藏只能作为明确记录的后备方案，避免切镜时楼房突然消失。
- 增加地面层次时处理真实高差和网格边缘；已有 16 位深度精度限制，避免大量几乎共面的铺装贴片。不要通过调大相机近裁面破坏第一人称手部。
- 静态构件按空间组团合批，保留组团裁剪能力；重复物件按测量结果使用实例化。不要把整个城市合为一个永远绘制的超级网格，也不要每块砖一个 draw call。
- 移动端优先简化远窗、花盆细节和远处行人，保留决定空间的建筑体量、路缘与植被团块。透明植物、雨水和灯光叠加要控制过绘，不给每盏装饰灯都加真实点光源。
- 动态随机序列在构建期生成；继续保留动画期间不调用 Math.random、鸟群池复用与切场资源释放约定。路径上的行人转弯、停留有目的，避免所有人同时循环摇摆。
- 保留球员面部、骨骼枢轴、投篮姿势、拾球坐标和篮筐碰撞参数；此计划没有要求重做玩法或扩大探索地图。

## 6. 验收清单

- 八场同一组真实第一人称、跟随与转播镜头，五架及额外投篮点，横屏/竖屏；检查菜单环绕、转场、蓄力、出手、取球和点位移动。截图标明场景、机位、视口与时间状态。
- 每场一张俯视布局、一张侧向剖面或宽景、三个常用玩法机位前后对比；开放场景额外验证海面/湖面与主题远景可见性。
- 每张图能回答：玩家从哪来；观众为什么待在这里；楼与路/树与土如何相接；远处通向哪里。用途、连接和空间关系必须出现在画面里。
- 不出现楼间露出世界底板、物体漂浮、路径穿墙、全场等距摆放同一种植物或观众、整片无用途场外铺装。
- 球员、球、篮板与篮筐轮廓始终清楚；高反差小细节和快速动态不能集中抢占投篮视线。
- 跑 `node scripts/check.js`、`node scripts/world-places.test.mjs`，扩展 `scripts/world-wonders-camera.test.mjs` 覆盖八场与上述主体。结构检查与射线通过后仍需实际画面验收。
- 在同视口、同机位、同设备下记录改前后 draws、三角形、帧时间及切场后内存。先测基线再定预算；真实手机需单独验收，桌面触屏模拟不等于真机帧率。
